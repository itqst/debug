# 坤坤调试台

设备调试工具，PySide6/Qt 桌面应用，目前接的是机器狗（L2 / L2W），以后可接飞机等其他设备。

## 运行包

`dist/KunKunDebug/KunKunDebug.exe` 是打好的单目录运行包，不需要另装 Python，目录可放在中文、空格或网络路径下。使用者文档见 `docs/使用说明.md`（包内同名文件）。重新打包：在 Windows 上运行 `build_windows.bat [输出目录]`（PowerShell 里写 `.\build_windows.bat`），默认输出到项目下的 `dist\`；第一次运行会建 `.venv-win` 并装依赖，连 PyPI 慢时先设镜像，例如 PowerShell 里 `$env:PIP_INDEX_URL = "https://pypi.tuna.tsinghua.edu.cn/simple"`。cadquery-ocp（STEP 导入）只有 Python 3.11 及以下的安装包，`.venv-win` 要用 3.11 或 3.10 建，否则打出的包不能导入 STEP，脚本结束时会提示。版本号只在 `dog_debug/__init__.py` 的 `__version__` 改，程序标题、诊断包和 exe 文件属性都从这里取。环境自检：`KunKunDebug.exe --self-check 目录`。图标由 `tools/make_icon.py` 从程序里的标志生成。

Linux（Ubuntu 22.04 x86_64）运行包用 `build_linux.sh [输出目录]` 打，参数和 Windows 版相同，产物 `KunKunDebug/KunKunDebug`；Qt 需要的 `libxcb-cursor.so.0` 在构建机上找得到（系统库或 `DOG_EXTRA_LIBDIR`）就一起打进包里，目标机不用另装。`DOG_PYTHON` 指定装好 requirements.txt 的解释器。构建机系统 Python 里的旧 matplotlib、pkg_resources 会被 PyInstaller 带进来和 numpy 2 冲突，脚本里已排除。运行包同样支持 `--self-check 目录`，Wayland 和 X11 下都验过

## 启动（Windows / PyCharm）

入口只有项目根目录的 `main.py`。Windows 解释器用 `build_windows.bat` 建好的 `.venv-win\Scripts\python.exe`（依赖都装在里面），也可以用环境变量 `DOG_PYTHON` 指定别的解释器。

PyCharm：

1. 设置 → 项目 → Python 解释器 → 添加解释器 → 添加本地解释器 → 选择现有，选 `.venv-win\Scripts\python.exe`，确定
2. 右上角运行配置选 `坤坤调试台`（在 `.idea/runConfigurations/KunKunDebug.xml`，已指向 `main.py`、工作目录为项目根），点运行

项目里的 `.venv` 是 WSL 下的 Linux 环境，没有装依赖，Windows 上不要选它。

不开 PyCharm 时，双击 `start_windows.bat`，或在 PowerShell 里进到项目目录执行：

```powershell
.\start_windows.ps1 -Demo
```

换电脑时，用 Python 3.10+ 创建独立环境，执行 `python -m pip install -r requirements.txt`，然后 `python main.py`。

## 启动（Linux / WSL）

需要可用的桌面显示（例如 WSLg）及 Linux 版依赖：

```bash
cd 项目目录
python -m pip install -r requirements.txt
python main.py --demo
```

依赖需要安装到你选定的解释器。程序不会自动安装系统软件、连接机器狗或修改配置。

## 现在可以做什么

- 协议目录 84 条（58 条控制方法），来自整机云端协议、设备端 local 协议、点云数据协议和 FSVR 现行协议文档，含来源和待核差异；只代表这些文档登记的方法
- GW 上线/心跳/配置请求的沙盒应答演示
- 全链路内存模拟：云端命令→Mock GW 路由→Mock 模块→本地 ACK→云端回复
- 经真实 GW 下发 MQTT 命令，或直连模块（直接发本地 command Topic）
- 雷达点云：收 ros2bridge 本地点云和 GW 上云的 `pcd`，按协议解码（`xyz_i16_i8`，长度、encoding 不对就提示不硬解），挂在 3D 机身上按高度或强度着色，显示点数、频率、时效；导航与文件页发 `pcd_switch` 开关采集并显示 ros2bridge 心跳；入库只存元数据，原始点只在内存
- 3D 观察区：遥控页和控制调试页右边常驻，切页不丢模型、镜头和轨迹，比例可拖；内置 L2 点足 / L2W 轮足；可导入任意 URDF（文件/目录/zip，package:// 与中文路径，缺资源可选目录重试）、STEP/STP（OpenCASCADE 读取网格化，结构查看）、STL；位置航向跟随 OSD，关节动作是演示，不是设备遥测
- 遥控页：页头显示最近一条指令的 ACK；运动方向盘（按住 5 Hz 连续发送，松手/失焦/断线即停并补发零速）、姿态动作、云台与镜头、拍照录像直播 AI 音量
- 导航与文件页：建图定位、单点/多点航点导航、媒体与点云同步、红外测温、喊话；设备应答回填地图、文件列表和温度
- 控制调试页：全部指令收在弹出目录（中文名 + method，可搜），“最近”一键回到发过的指令；切换指令保留未发出的草稿；编辑在上、本次结果在下
- 连接配置：侧栏“⋯”把当前填写存成有名字的配置（不存密码），下拉一选就填好；连上后显示每秒收到的消息数
- 遥测卡电量、速度、航向、温度带最近 60 秒走势线（只画真实 OSD）；3D 左下角航向表和速度
- 消息详情下方列出和上一条同设备、同 Topic、同方法消息相比变了哪些字段
- 任何页面 Ctrl+K 打开指令目录
- 日志回放：3D 区“回放日志”选一个带 OSD 的会话，拖动或播放逐帧看位置、航向和遥测，旁边列出到这一帧为止最近的指令、ACK、状态，双击看证据链；按日志行序回放，不按跨机时钟算延迟
- 浅色 / 深色外观：侧栏标题旁 ◐ 切换，记住上次选择
- 实时 MQTT 监听，指令、ACK、状态、事件分栏归类
- 消息页默认按请求聚合：失败、无 ACK 置顶，一行看结论、耗时和链路；双击看逐条原文；按模块、类型、方法、文字筛选，“只看失败”快速定位
- 一键导出诊断包 ZIP（请求结论、脱敏会话、所选请求、运行环境）
- 请求可加问题备注（预期/实际/备注/已复现），随诊断包导出
- 检测链路视图：抓拍 → JPEG → 登记 → 上传受理 → 上传终态 → 终态确认 → 本地事件 → 云端事件八段显示，指出卡在哪一段
- 导航与文件页可打开 PGM 地图，点地图添加航点
- 点消息看同设备、同连接/导入会话、同 tid 的证据链、具体错误与排查建议
- 日志/JSONL 拖入或选择导入，后台解析、进度和剩余时间、可随时停止，入库前脱敏凭据，可打开原文附近，不修改原日志；可查看和清空本地数据
- 最近状态总览，一键打开现有 WebRTC 网页和复制房间号
- 保存/加载 YAML 沙盒用例，内置九组语义回归
- 导出脱敏 JSONL，会话 SQLite 自动保留在用户数据目录

## 最快试用

1. 启动后左下角保持“沙盒 · 全链路模拟”
2. 控制调试页右上角点“演示一次故障定位”，或选 `take_photo`、沙盒结果选“执行失败”后点“模拟发送”
3. 编辑区下方的“本次结果”直接显示：MEDIA 返回失败、具体原因、下一步，以及完整证据链
4. 消息追踪页用顶部分段按模块/类型筛选，打开“只看失败”，点任一行看证据链
5. 日志文件直接拖进窗口即可导入

## 连接实际 MQTT

1. 左下角选“云端 → 真实 GW”或“直连模块”，填 Broker、端口、狗 SN 和账号
2. 点“连接”，连上后选指令、改 JSON、点“发送”，控制页编辑区下方实时显示 ACK 和状态
3. 所有协议指令（含运动、云台）都可以直接发送；Topic 和 JSON 都可手改，便于发异常报文测试设备处理
4. MQTT 未连接时发送直接报错，不排队，避免重连后补发旧的运动指令

只监听 `tta/robotdog/<当前SN>/#` 和 `local/robotdog/#`，本地 Topic 本身通常没有狗 SN，接入前确认当前 Broker 对应哪个设备。

## 明确未完成的范围

这是可运行的调试工具，不是整机实测全部通过的交付版。有按钮不代表该功能已在真机上验证。

**未做真机验证**

- 已只读接入实机 Broker：OSD、各模块状态和版本、心跳、ZLM 流列表都按实际数据核对过；控制和运动指令下发、按正确云端链路发请求看回执，这几项还没在真机上验
- 运动连续发送 5 Hz、松手/失焦/断线停止只在本机测试，设备端实际停车时间未核；PTZ 停止时间未核
- OSD heading 按角度、0° 对齐场景 x 轴是假设，方向待真机核对
- 点云：本地 ros2bridge 点云的格式按实机抓到的报文核过；经 GW 上云的 `pcd` 只按协议文档和沙盒，实机建图时还没看；雷达安装位置协议没给，3D 里按“离地”输入框（默认 0.45 m）画，没核雷达朝向
- 多显示器、高 DPI 缩放只在本机 1480×940 / 1180×720 两种窗口下检查过；没在未装 Python 的干净电脑上跑过运行包

**协议/资料缺口**

- UDP 云控未接，报文、会话和认证资料未提供
- 压缩地图应答（`get_all_compressed_pgm_map`）的图像编码文档没给，不能直接从应答出图；PGM 文件预览、yaml 参数和点地图加航点已可用
- `attitude_control` 文档示例 10 与声明范围 ±0.5 rad/s 冲突，单位未核，只提供 JSON 编辑
- `ir_palette_set` 文档没有有效请求样例；导航路径管理文档标“未使用”；这两类仍用 JSON 编辑
- 航点/内部抓拍/登记上传专用方法已入目录用于观测，依赖完整上下文的真实发送尚未接

**3D**

- 内置模型是 URDF + STL（资料里没有狗的 STP 原档）；STEP 导入用自制装配样件验证，狗的真实 STP 待样本；ULTRA 环视版 RAR 未接；URDF 网格只支持 STL/OBJ（DAE 需先转换）；设备不上报关节角，腿部动作只能演示
- 日志编码支持 UTF-8（含 BOM）和 GB18030/GBK；UTF-16 不支持；混合编码的行会标出行号

**性能与数据**

- 1 GB 日志实测导入约 6.5 分钟、本地库约 6 倍日志大小；冷门词全文搜索约 25 秒（后台执行，不卡界面）；未建全文索引
- 同批导入的文件按同一设备/会话处理，混合设备日志请分批导入
- 导入日志不计算跨主机精确时延；原文无 Topic、tid 或设备字段时不臆测链路

**其他**

- 结果解释有覆盖主要方法的规则，不保证自动识别所有根因
- 模板中部分地图 ID、上传地址、相机 SN 是示例，真实发送前按设备修改
- 用例只在沙盒执行，尚无向真机批量回放
- 设备版本只从心跳/subsystem_state 的 version 字段读取，显示在状态卡右上角
- 检测链路只按消息里实际带的关联字段并链，真实设备各模块是否都带这些字段尚未用真机日志核对；并链假设检测图文件名、tid 不会重复（契约里是带随机串的路径），出现重名时会并到一条


测试包括：结果层级、活跃状态、中文、跨设备同 tid、上传终态、JPEG 边界、脱敏存储、日志多行/截断、Qt 操作以及实际 Paho TCP 收发。沙盒回归只证明工具解释行为，不代替机器狗实测。
