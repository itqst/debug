# 坤坤调试台 使用说明

设备调试工具，目前接的是机器狗（L2 / L2W）。用来发指令、看 ACK 和状态、导入日志查故障、导出诊断包，以及查看设备 3D 模型。

## 启动

**运行包（推荐）**：双击 `KunKunDebug\KunKunDebug.exe`。不需要另装 Python。整个 `KunKunDebug` 目录可以放在任意位置，中文、空格和网络路径都能运行。从网络路径（如 `\\wsl.localhost\...`）双击启动时，Windows 可能弹出“打开文件 - 安全警告”，点“运行”即可；复制到本机目录就不会弹。

**源码运行**：用项目 Windows 环境运行根目录 `main.py`，或双击 `start_windows.bat`。

**环境自检**：在命令行执行下面这条，会检查依赖、内置模型、STEP 读取和 3D 视图，报告写入 `自检目录\self_check.txt`：

```
KunKunDebug.exe --self-check 自检目录
```

本地数据保存在用户数据目录的 `sessions.sqlite3`，重开后会话和备注都还在。需要清空时，在“日志排障”页点“清空本地数据”。

## 连接方式

| 方式 | 发到哪 | 用途 |
| --- | --- | --- |
| 沙盒 · 全链路模拟 | 不联网，不发 | 程序自己模拟 GW 转发和模块回复，熟悉工具、演示用；**狗不会动**。切过来时会先补发停止再断开已有连接 |
| 云端 → 真实 GW | `tta/robotdog/<SN>/services` | 扮演云端平台，测整条链路：GW 收到后转给模块，结果回到 `services_reply`；Broker 填 GW 对接云端用的那个 |
| 直连模块 | `local/robotdog/<模块>/command` | 跳过 GW 直接发给模块（和在 MQTTX 里直接发本地 Topic 一样），Broker 填狗上 GW 板的地址、端口 1883、账号留空 |
| 离线日志分析 | 不发 | 只分析本地历史：切过来时补发停止、断开实时连接、停掉 ZLM 查询，并跳到日志排障页导入日志；发送按钮变灰 |

**远程（FRP）**：狗不在身边时，连接方式选“直连模块”，打开“经远程（FRP）”，填整机 SN 和 SSH 账号密码（本机记住），点“连接”。上位机经 FRP 代理（124.126.230.115:22222）用 SSH 登录 `<整机SN>.tta_edge.com`，把狗上的 Broker 和 ZLM（80）转到本机，之后和在狗旁边直连完全一样：发指令、看 ACK、状态总览、ZLM 都照常用。Broker 地址不用填：上位机读狗上的 `/oem/ttaviation/gateway/db/mqttBroker.cfg`，GW 连哪个 Broker 就转哪个。大多数狗 Broker 就在登录的这块板子上；也有狗是登录到 NX、Broker 在 192.168.234.1，同样自动转过去，连接状态里会写明连的是哪个。读不到这个文件时按登录板子本机的 1883。第一次连会记下设备的 SSH 主机密钥，以后对不上就不登录。FRP 代理偶尔会拒绝（404）或断开，提示后再点一次连接即可。

例如“开启直播”：data 都是 `{"index": 1, "sn": "002", "state": 1, "stream_type": "webrtc", "mode": 2}`，云端方式外面包 method、tid、target（vision）、ts 发到 services；直连方式发的和 GW 实际转给模块的一样：去掉顶层 target，其余不变，发到 `local/robotdog/media/command`。

直连时发往哪个模块按 GW 的路由算，不按指令目录里的分类：拍照、录像、直播（云端 target 是 vision）发给 MEDIA；喊话器两条发给 `audio`；文件和地图的四条（云端 target 是 gw）发给 FSVR。FSVR 的删除、查询、确认四条扩展指令只能直连，当前 GW 不接受 target=fsvr。

云端回复的外层 `data.result` 是 0 不一定代表成功：GW 通用转发只读模块回复根上的 result，MEDIA、PTZ 等把结果放在 data 里，真实结果在 `data.data.result`。工具按里外两层一起判断，沙盒也按这个形状模拟。

## 常用流程

**先体验**：左下角保持“沙盒 · 全链路模拟”，在控制调试页点“演示一次故障定位”。

**发指令**：
1. 左下角选连接方式（区别见下面“连接方式”），真实模式要填 Broker、端口和 SN，再点“连接”。常用的连接点旁边的“⋯”存成配置，下次在下拉里一选就填好（密码不保存）。连上后右下角显示每秒收到多少条消息，是 0 就说明没数据进来。
2. 控制调试页点“全部指令”（任何页面按 Ctrl+K 也行）选指令（中文名和 method 都能搜，回车选第一条），在“参数”表单或 JSON 里改值，点“发送”，下方直接看结果。切到别的指令再回来，没发的修改还在；点“恢复模板”才会清掉；同样参数想再发一次就点“换新 tid”。发过的指令出现在“最近”里，点一下就回到它。
3. 也可以直接发异常报文：JSON 无效或不是对象时会按原文发送。

**遥控**：遥控页按住方向键移动，右边的 3D 模型同步走，松手、切走页面或窗口、断线都会停，并补发一次零速；键盘 WASD 移动、QE 转向、空格急停。导航与文件页可以建图、做航点导航，打开 PGM 地图后点一下就能加航点。

**查故障**：
1. 消息追踪页默认“按请求”显示，失败和无 ACK 的排在最前。
2. 单击看证据链；双击只看这次请求的逐条消息，点“仅此请求 ✕”回到全部。
3. 导入的日志可以点“原文附近”看原日志前后内容。
   - 同一台设备的其他来源（导入的日志、实时跟随、另一次连接）里有相同 tid 时，证据链下面列出“其他来源中相同 tid 的记录”，写明来源、条数和发生时间。点“查看”在原地看那一组，点“‹ 回到原来那组”回来。各组分开看，不拼成一条；tid 可能被复用，同 tid 不一定是同一次操作。
   - 点证据链右上角的“这段时间的设备日志”，跳到日志排障，自动列出这个模块在请求前后各 30 秒的日志（按日志里写的时间）。这只是按时间圈出来的，不一定和这次请求有关；设备时钟不准就自己放宽时间段。没有日志时，点提示条上的“从设备取日志…”，模块和时间已经选好（按文件修改时间挑整个文件）。点“‹ 回到请求”回到原来的页面，列表和选中都还在。状态总览的“指令与回复”里点开请求也有这两项。
4. “检测链路”视图按 抓拍 → JPEG → 登记 → 上传受理 → 上传终态 → 终态确认 → 本地事件 → 云端事件 八段显示，直接看出卡在哪一段。
5. 点“备注这次请求”记下预期、实际和备注。
6. 点“导出诊断包”，先看概览再选保存位置。包里是脱敏后的数据，不含原始日志和密码。

**导入日志**：把日志文件拖到窗口任意位置即可。支持 UTF-8（含 BOM）和 GBK/GB18030；混合编码的行会标出行号；UTF-16 不支持。

导入完成后就在“日志排障”页看，不用切到消息页：
- 上面的下拉框选范围：第一项是当前设备导入过的全部日志，后面是各批（默认刚导入的那批）。实时收到的和沙盒消息不会混进来
- 旁边选时间：全部时间 / 最近 30 分钟 / 最近 2 小时 / 今天 / 选时间段…（选了会出现起止两格）。按日志里写的发生时间筛，不是导入或下载的时间；原文只有时刻、没有日期的行算不出日期，按时间筛时不计入，条数旁边会写有多少条。筛出来的某一行点开，看到的仍是整条请求（窗口外的回复也在）
- 搜索框搜原文（中文、tid、错误码都行），可以按模块筛，打开“只看错误”只留失败回复和带错误字样的文本行
- 表格里“原文时间”是日志里写的时间，不是导入时间；“内容”是原文。鼠标停在行上能看更长的原文、文件名、行号和导入时间
- 点一行，右边显示详情：带 tid 的行列出这次请求的全部消息（指令、ACK、云端回复），普通文本行显示整行原文；点“原文附近”看原日志前后几十行
- 编码、sha256、耗时等导入记录收在左下角“导入记录 ▸”里，要看再展开

**从设备取日志**：不用先登板子下载。日志排障页右上角点“从设备取日志…”，勾模块、选时间段（最近 30 分钟 / 2 小时 / 12 小时 / 设备上保留的全部），上位机经 SSH 读狗上 `/userdata/gw_logs/<模块>/` 的日志文件，存一份到本机数据目录的“设备日志/<SN>/”，然后自动作为一批显示在这页。远程时走 FRP；在狗旁边直连时连 Broker 地址的 22 端口。只读，不改设备上的东西。

**实时跟随**：打开右上角“实时跟随”，各模块新写的日志会逐条加到“实时跟随中”这一批里，可以一边操作一边搜、筛错误、点开看。关掉开关、断开连接或关窗口就停。每开一次是新的一批，停了以后批次名写起止时间和条数，比如“实时跟随 · 11-02 16:48–17:03 · 15618 条”。实时跟随的内容只存在本机，最后一行超过 48 小时的批次会自动删掉；要找回更早的，用“从设备取日志”按时间段再取。导入的批次不会自动删。

**无人机**：连接卡里“设备”选“无人机”后，左侧导航整个换成无人机的页面，狗的页面都收起来；选回“机器狗”再换回来。无人机的主题里不带 SN、只走局域网，所以选无人机时 SN 和 FRP 不显示。方式选“直连模块”，填板上 Broker 地址，点“连接”，连上后只订阅 `local/uav/#`，连接期间不能换设备，断开后才能换。

无人机的功能还会随协议补全继续加，目前先保证 VFC 和 Bridge 对接看得清、指令发得出去：
- **控制调试**：指令目录换成两组。**VFC 任务**（模拟 GW 发给 VFC，Topic `local/uav/vfc/command`）：开始航线、暂停、继续、结束航线、返航、降落，报文是本地格式 `{method, tid, bid, ts, data}`，不带 target，tid、bid 自动生成。**Bridge**（模拟 VFC 发给 Bridge，Topic `local/uav/bridge/command`）：读状态快照、启动/停止任务环境、取消启动、延后重定位、放行下一个航点、暂停/恢复导航、返航、解除 next 不确定锁、降落，报文是 `{sn, id, type, action, args, client, ts}`，id 自动生成，参数表单改的是 args。VFC 没在跑时可以用 Bridge 这组单独测桥接层；VFC 在线时也能发，但会绕开 VFC 的状态机，发出后提示一句。发出后“本次结果”里看 ACK 和证据链
- **航线任务**：上面是当前任务（VFC 任务状态和 bid）和暂停/继续/结束航线/返航/降落快捷按钮，快捷指令带新 tid 和当前任务的 bid；下面直接编辑航线，表格填 x、y、z 和航向角 yaw（度），发出时换成四元数（yaw 0 就是 0,0,0,1）；动作一栏留空，VFC 现在不支持航点动作，填了整条航线会被拒。bid 自动生成，点“换新 bid”可以换。点“发送航线”发 start_multi_nav_by_points，填错时写明第几个航点。控制调试页发 VFC 指令时 bid 也自动带：开始航线没填就新生成，暂停、继续、返航、降落带当前任务的 bid
- **消息追踪**：和狗一样，看全部报文
- **状态总览**：Bridge 的在线、任务环境、定位、重定位、导航、建图、飞控、位姿，VFC 的在线、任务状态、航点进度。颜色看数据本身（正常 / 失败 / 未知 / 不适用），下面一行看收到的时效：按本机收到的时间算（板上时钟不准），超时写“超时没收到新上报”，订阅时 Broker 给的保留消息写“保留快照”。`local/uav/vfc/command`、`local/uav/bridge/command` 上有保留消息时顶部红色常驻告警，请在 MQTTX 里往这个主题发一条空的保留消息清掉。下面是关键变化（到点等待放行、转向完成、navigation.next 发出等标蓝加粗）和指令时间线（Bridge 命令 5 秒内就近配到 VFC 指令下面，VFC 自己发起的 next、stop、status 标“VFC 自动”）。点卡片右侧展开这个领域的详情（和狗的状态总览一样）：“状态上报”看最新一条的完整字段，和上一条比变了的标橙并写原值，下面列这次连接里每次报文变了哪些字段；“相关指令”列这次连接里和它有关的指令（任务环境是 system.*、job.*，导航是 navigation.*，VFC 的卡是 VFC 指令），点一行看整条请求。一直没收到的卡写可能原因（如“VFC 服务可能没在跑”“Bridge 报 ros DOWN，没有位姿可发”）。右上角“导出本次报文”把这次连接的全部消息存成 jsonl
- **日志排障**：只能导入文件（nav 的抓包可以直接拖进来），“从设备取日志”和“实时跟随”是狗的，选无人机时不显示

**发送开关**：默认只读，要发先打开连接卡里的“允许向无人机发送”，每次重新连接都会自动关上。打开后也只放行上面两个指令主题，QoS 1，Retain 固定关，狗的指令不会发到无人机上。连上后不会自动发任何东西。

**状态总览**：每个模块一张卡片（GW、VFC、PTZ、MEDIA、VISION、FSVR、ROS2BRIDGE、ZLM），显示当前设备（连着时是连接的 SN，没连时是左侧填的 SN）最近的模块上报和版本。导入的日志和别的设备的消息不会出现在这里，导入的日志到日志排障页看。

点卡片，右侧展开这个模块的详情，顶部可以切两种：
- **模块上报**：模块自己主动报的状态、心跳，各类最新一条的完整字段，和同一路的上一条相比变了的字段标成橙色。MEDIA 多一份两路推流情况，VISION 多一份最近的检测事件。这些不是哪条指令的回复。
- **指令与回复**：一次请求一行，新的在前，结果按整条请求算（没收到回复就写“无 ACK”）。只收到回复、没看到指令的请求也会列出来，备注写“仅观测到回复”。本机发送记录、Broker 回显和各段回复合成一行，不是发了多次；它们分别是在哪看到的，鼠标停在行上能看到。注意：观测到发往模块只说明 Broker 上有这条指令，不等于模块已经执行；收到成功回复也只说明模块这样回了，动作有没有做完要看后续状态。

可以按方法筛选（中文名或 method）。点一行，就在这里看整条请求：指令原文、对应 ACK、原始 JSON 和“原文附近”。点“‹ 返回列表”回到原来的位置和选中行；要跨模块、看历史，点“在消息追踪里看”。

音视频预览里的房间号是“整机SN_相机SN”（例如 10300262998249_002，一个相机一个房间），跟着左侧的整机 SN 和遥控页当前选的相机自动填。直播两路表格里的房间是设备实际上报的值，和整机 SN 不一致时照实显示。

云端上报的 `subsystem_status` 会按模块拆开，分别显示在对应的卡片上。

信息太多时，用页头右上角的两个按钮筛选，可以多选：“模块”选只看哪几张卡片，“状态类型”可以取消心跳、子系统在线这类不关心的状态。例如查视频时，只选 MEDIA 和 ZLM，只留视频流状态和直播房间状态。筛选只影响这一页显示什么：消息照常接收、保存；卡片上的绿点、版本也照常计算，隐藏了心跳不会让模块显示成过期。被筛掉的会明确写“当前筛选无匹配状态”。不选 MEDIA 时，直播两路和音视频预览一起收起。筛选会记住，下次打开还是这样，点“恢复全部”回到全部显示。

ZLM 是开源流媒体服务器，不往 MQTT 上发状态（它的日志在板子上用 `journalctl -u tta_zlmediakit.service` 看），工具通过它的 HTTP 接口查。打开 ZLM 详情，填 ZLM 地址和 secret（在设备 ZLM 的 config.ini `[api]` 段），点“查询”，就能看到当前有哪些流、多少人在看、码率多少。用“直连模块”连上狗后，地址会自动填成狗的 IP:80，换狗、换网时跟着换；ZLM 不在狗上时可以手填，手填的地址会记住、不再自动改。secret 填一次就记住，以后打开状态总览自动查，停在本页时每 3 秒刷新一次，连不上或 secret 不对会直接写明原因。推流在不在跑看 MEDIA 的 `stream_status`（result 1 为打开、0 为关闭），ZLM 里有没有这路流看 ZLM 详情，两边对着看。

**拉流看画面**：ZLM 详情里每路流前面标了是哪种画面：
- **相机原始**（`live/__input_video0` 这类）：相机直出的画面，Media 内部用，一直都在
- **原画转发**（`live/video0`，直出模式）：把相机原始画面原样转出来
- **AI 处理后**（`live/video0`，AI 模式）：RK 叠加检测框等处理后推回来的画面

点“播放”会弹一个窗口拉这路流，下面写着地址、编码、分辨率和帧率；可以同时开几个窗口，把原始和处理后的画面放在一起对比，关窗口就停止拉流。“复制地址”复制这台电脑拉流用的地址，可以粘到 VLC 等播放器里。有 FLV 或 TS 的流走 ZLM 的 HTTP 端口；只有 RTSP 的（相机原始）走 ZLM 的 RTSP 端口（查询时自动从 ZLM 读）。远程（FRP）时也能拉：HTTP 走 80 端口那条隧道，RTSP 第一次播放时自动再开一条隧道，复制出来的是本机隧道地址，断开远程就失效。只拉流，不改设备上的任何设置。

**拉流地址列表**：状态总览“音视频预览”下面的下拉里列出这只狗能拉的所有地址，不用自己填：
- 来源：连上狗后，上位机经 SSH 读设备的拉流配置（RK 上是 `media.cfg`，NX 上是 `vision.cfg`），再加上 ZLM 查到的流；点“从设备读取”可以重读。ZLM secret 没填时也会顺手从配置里填上
- 每路相机列出：相机直连（不经 ZLM，相机自己的地址）、ZLM 相机原始、ZLM 原画转发或处理后（AI）的 RTSP / RTMP / HTTP-FLV / HTTP-TS 等各种协议；推流协议配成 RTMP 时还有云端 RTMP（按配置里的模板拼，现场可能被 GatewayOnlineInfo.cfg 换掉）；ZLM 上别的流也列在后面
- 选一项点“拉流播放”，或“复制地址”粘到 VLC。也可以直接在框里填别的地址，用过的记在下拉最后（最近 8 个）
- 远程（FRP）时所有地址都自动经狗转过来，相机在狗内网里也能拉；窗口和提示里的密码显示成 ***
- 远程拉流受 FRP 线路带宽限制：实测经 FRP 只有约 800 kbps，而一路 1080p 流要 1.5~2 Mbps，所以远程点开后要等 15~20 秒才出画面，之后也会卡、掉帧。窗口下面的“收到 N kbps”就是实际收到的码率，比流本身低很多就是线路不够。要流畅看就在狗旁边走局域网，或者拉码率低的那路（比如 `__input_video1` 约 0.4 Mbps）
- 读不到配置（没填 SSH 账号、没权限、文件不在）时下面会写明原因，ZLM 那部分照样列

**雷达点云**：狗上的 ros2bridge 把 NX 激光雷达的点云稀疏后发到 `local/robotdog/ros2bridge/data`（约 2 Hz、每帧约 5400 点），GW 在建图中再转成云端 `tta/robotdog/<SN>/state` 的 `method=pcd`。两路收到的都会画在 3D 区，挂在机身位置上（点在雷达坐标系里，随狗移动），同一帧从两路各来一次只算一次：
- 3D 区模型信息下面一行：“点云 · 实时 / 已停 / 未收到”，显示开关，按高度或强度着色，“离地”是雷达原点离地高度（只影响显示，安装位置协议没给，默认 0.45 m），“清除”去掉当前这帧；再下一行是点数、稀疏体素、精度、频率和多久前。3 秒没新帧时点变淡，最后一帧留着
- 导航与文件页“雷达点云”卡片：“开始采集 / 停止采集”发 `pcd_switch`，哪种连接方式都发本地 Topic（云端没有这条指令），下面实时显示 ros2bridge 心跳（是否在采集、雷达和输出频率、码率）和最近一次回执
- 正常不用手动开：GW 在建图中（`mapping_status` result=5）自己打开、建图结束关掉。不建图时手动打开，GW 最快 5 秒后会按心跳把它关回去；只想看点云就先停 GW，或在设备 `ros2bridge.cfg` 里把 `ros.start_enabled` 设成 true
- 点云解析不了（encoding 不认识、长度和 count 对不上）会提示一次，不硬解
- 点云一条约 50 KB，入库时只存元数据（点数、scale、seq 等），`points` 换成一句说明；所以消息页和诊断包里看不到原始点，回放日志也不放点云
- 沙盒里在导航与文件页点“开始采集”，会生成几帧演示点云（一个房间），离线也能看效果

**日志回放**：导入带 OSD 的日志后，点 3D 区右上角“回放日志”，选会话。拖动时间条或点 ▶ 播放，模型按当时的 OSD 走，下面列出到这一帧为止最近的消息，粗体是刚发生的，双击跳到消息页看证据链。回放时位置标签和航向表显示“回放”，实时 OSD 暂不驱动模型，点“退出回放”恢复。

**外观**：侧栏“坤坤调试台”旁的 ◐ 切换浅色 / 深色，下次打开沿用。

**3D 模型**：遥控页和控制调试页右边都有 3D 模型，中间的分隔条可以拖动调比例。模型区右上角可以切换内置 L2 点足 / L2W 轮足，也可以点“导入模型”：
- **URDF**：选 .urdf 文件、模型目录或 zip。找不到网格时会列出缺哪些文件，可以选资源目录重试。
- **STEP / STP**：只做结构查看，按文件单位自动换算成米。
- **STL**：导入时选毫米或米。

位置和航向跟随设备 OSD；设备不上报关节角，腿部动作只是演示。

## 快捷操作

- 表格选中后按 Ctrl+C：逐条视图复制消息 JSON，请求视图复制结论和 tid
- 滚轮滚动页面时不会误改滑条和下拉框；点中控件后滚轮才会改值
- 3D 视图：左键旋转，滚轮缩放，中键或 Ctrl + 左键平移；“适合”和前、侧、顶、等轴视角一键切换
